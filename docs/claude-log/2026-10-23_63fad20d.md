Done. The fork is installed, built, pushed, and planned.

**What I found.** GridCraft is not a JavaScript app but a 160k-line pure-Rust spreadsheet (egui UI) at v0.11.1 with 1,753 commits. It already has the pieces an LLM needs: every ribbon action is a command, and all commands are reachable through an MCP server, a CLI and a JSON control channel. It has no LLM client, no chat UI and no MaluOS integration. Its licence is MIT or Apache-2.0, but forks must remove the ArtCraft brand files, which I did.

**What I did.**
- Installed Rust 1.99.1 with the wasm target and the Linux build libraries on this dev VM.
- Created the public repo github.com/maludb/malu123 and seeded it from a clone at ~/malu123 with full upstream history. The remote `upstream` points at storytold/gridcraft so merges stay cheap.
- Built the CLI and desktop app in release mode under a memory-capped cgroup (the dev VM dies on page-cache pressure). Formula eval, a command run on a sample workbook, XLSX output and the MCP server with 21 tools all work. The desktop binary built but has not been launched since the VM has no display.
- Wrote the plan at docs/malu123/plan.md, a status page, a new README, and a Malu123 section at the top of CLAUDE.md. Two commits, M0.1 and M0.2, are pushed to main.

**The plan in short.**
1. Phase 0, foundation: fork, toolchain, get the upstream CI gate green here, decide renames.
2. Phase 1, ship Malu123 as a plain spreadsheet: rename the apps and packaging, MaluOS deb in the maluos repo, boot test, release on apt.maluos.com.
3. Phase 2, an LLM client crate: one trait with backends for the MaluOS gateway and local agent sockets, the Claude API via the vault, and OpenAI-compatible servers.
4. Phase 3, the assistant crate and pane: workbook context builder, tool schema shared with the MCP server, a plan-and-act loop that only runs engine commands as one undoable group per turn, with read-only, confirm and autopilot modes.
5. Phase 4, ask me anything depth: explain formulas, big-data questions via formulas and pivots, charts by description, imports, per-workbook memory, office agent delegation.
6. Phase 5, track upstream's beta gates by merging.

**Decisions I left for you** (listed at the end of the plan): the default provider on MaluOS, whether to keep `gridcraft-*` crate names (recommended), whether to ship the web build, and the app id.
